# INQVEXA — Next.js website (inqvexa.com)

Production Next.js (App Router, TypeScript strict) build of the approved INQVEXA design — 16 pages, generated directly from the approved design files so layout, copy, colours, spacing and internal links match exactly.

## Quick start
```bash
corepack pnpm install
corepack pnpm dev               # http://localhost:3000
corepack pnpm typecheck
corepack pnpm build && corepack pnpm start
```
Node 20+.

## How it is built
- **Server-rendered pages.** Every page in `app/**/page.tsx` is a Server Component with its own `metadata` (title, description, canonical `https://inqvexa.com/...`, Open Graph, Twitter) and JSON-LD exactly as approved (Organization, WebSite, AboutPage, CollectionPage, Service, BreadcrumbList, FAQPage, ContactPage, WebPage).
- **Page styles.** `app/globals.css` holds the shared rules; each route's `page.css` holds its own rules (keyframes, responsive breakpoints, light-mode overrides). Components keep the design's inline styles for 1:1 fidelity.
- **Shared chrome.** `components/SiteHeader.tsx` and `components/SiteFooter.tsx` are used on every page.
- **Interactive states without client JS bundles.** Tabs (Solutions, Services), the "Example workflow" players on solution pages, and the two animated homepage demos (Document Intelligence invoice extraction, AI Voice Agent call) are **pre-rendered for every state** in HTML (`data-sv` / `data-sv-v`). `public/inqvexa-site.js` only toggles which state is visible, following the timings in `<script id="inq-sv">`. All content is in the HTML for search engines.
- **Site behaviour** (`public/inqvexa.js`, loaded by `inqvexa-site.js`): dark/light theme with persistence, header auto-hide on scroll, mobile/tablet menu, page cross-fade transitions, floating Call / WhatsApp / Email / back-to-top buttons, FAQ accordion, card icon motion, swipeable tab bars, contrast guard, mobile refinements. Respects `prefers-reduced-motion`.
- **Contact form** (`components/ContactForm.tsx`, client component) with field-level validation shared with the server (`lib/contact.ts`), country-code search, honeypot and a small rate limit. It posts to `app/api/contact/route.ts`, which re-validates and emails **karthik.bm@inqvexa.com**:
  - via **Amazon SES** when `SES_FROM_EMAIL` is set (recommended), with the visitor as Reply-To;
  - otherwise via the FormSubmit relay (the recipient must click a one-time activation email).

| `CONTACT_TO_EMAIL` | server | `karthik.bm@inqvexa.com` |

## Deploy on AWS Amplify Hosting
1. Push this folder to a Git repository (GitHub, GitLab, Bitbucket or CodeCommit).
2. Amplify console → **Create new app** → connect the repo/branch. Amplify detects Next.js (SSR). `amplify.yml` is included.
3. **Environment variables**: add the four values above.
4. **SES**: in Amazon SES (same region) verify the domain `inqvexa.com` (adds DKIM DNS records) and request production access. Attach an IAM policy allowing `ses:SendEmail` to the Amplify **compute role** (App settings → IAM roles). No access keys are stored in the app.
5. **Custom domain**: Amplify → Hosting → Custom domains → add `inqvexa.com`. Make the apex `inqvexa.com` primary and redirect `www.inqvexa.com` → `https://inqvexa.com` (a matching redirect is also in `next.config.ts`). Amplify issues the SSL certificate and serves HTTPS only. If DNS is not in Route 53, add the records Amplify shows at your DNS provider.
6. After the first deploy, submit `https://inqvexa.com/sitemap.xml` in Google Search Console and Bing Webmaster Tools.

## Recommended follow-ups
- Run `npm run build` and fix anything your exact Next.js version flags (this project was generated and structurally checked, but not compiled in this environment).
- Light-mode visitors may see a brief dark frame on first load while `inqvexa.js` recolours sections; moving the light-mode palette into CSS variables removes it.
- The inline styles can be progressively refactored into Tailwind / CSS modules without changing the design.
